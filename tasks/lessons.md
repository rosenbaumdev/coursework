# Lessons — Pattern-Level Rules from Past Mistakes

Format: each entry is a rule, then **Why** (the incident or reasoning), then **How to apply** (when this kicks in).

---

## `wrangler r2 object get/put/delete` default to LOCAL state — use `--remote` for prod
**Why:** Debugging a prod 500 on the interview, I "deleted" the offending prod session ~5 times; each said "Delete complete" but the Function kept reading it. I chased a phantom "split store" (jurisdiction? two buckets?) for ~an hour. Root cause: `wrangler r2 object *` operates on the LOCAL `.wrangler/state` R2 by default; the deployed Function reads REAL prod R2. My deletes never touched prod. `--remote` immediately showed the real object (the Function's session, history included).
**How to apply:** Any time you inspect/mutate the data a *deployed* Worker/Pages Function sees, pass `--remote` (and the CF token). Local-vs-remote is the FIRST hypothesis when CLI and a deployed Function disagree about R2/KV/D1 contents — before jurisdiction or duplicate-bucket theories. Retrieve Zachary's profile with `wrangler r2 object get coursework-interview/profiles/zachary/<course>-profile.md --remote`.

## Old-schema persisted sessions crash new inventory code — guard on load, don't trust the store
**Why:** First prod run of the redesigned interview 500'd: a leftover session from the original 7-section machine (no `inventoryState`) hit the resume branch, and `requiredCounts`/`progressInfo` did `state[o.id]` on `undefined`. Local never saw it because local R2 had no such ghost.
**How to apply:** When a persisted object's schema changes, validate shape on load (`loaded?.inventoryState && typeof … === 'object'`) and treat a mismatch as "start fresh / overwrite," not as a resumable/completed session. A schema guard is cheaper and safer than trying to purge every stale record.

## Never `rm -rf` local R2 state to "get a clean test session"
**Why:** During Phase S.1 I wiped `.wrangler/state/v3/r2` on several dev restarts to force a fresh interview. That local R2 also holds the *saved interview transcripts* from every test walk — including Jonathan's. Wiping it destroys the exact data we need to diagnose interview behavior (drift, tag firing, pacing). Nearly lost his drift-test transcript; caught it only by inspecting before the next wipe.
**How to apply:** To reset ONE student's interview, delete just that session key, never the whole bucket. Better: leave sessions in place and read them (`find .wrangler/state/v3/r2/coursework-interview/blobs` → the blob is the raw session JSON). Treat local R2 interview data as real user data, because for diagnosis it is.

## Interview instrument: "feel heard" vs "work the 7 sections in order" is a live prompt conflict
**Why:** Haiku, given both "make him feel heard / follow every thread / NEVER rush [SECTION_COMPLETE]" and "cover sections in order, advance when done," obeys the first and ignores the second — froze at Section 1 for 4 turns while mining Section 4 content, never emitting the advance tag. Progress pointer is server-authoritative off that tag, so it stalls.
**How to apply:** Any section-gated LLM instrument needs (a) a crisp per-section exit criterion, (b) explicit "later-section topics are OFF-LIMITS until you get there," (c) advance-vs-linger *balanced* (over-staying is failure too, not just rushing), and ideally (d) a server-side pacing safety net so a stuck tag can't freeze the whole flow. Don't rely on a lone "emit the tag when done" instruction.

## Haiku 4.5 won't reliably emit backend control tags mid-conversation; Sonnet 5 + adaptive thinking does
**Why:** Phase S.2 rebuilt the interview as a granular objective inventory with `[TICK:]`/`[TABLE:]` tags. On Haiku 4.5 the identical prompt+walk emitted **0 ticks across 13 turns** — it ran a warm, high-quality interview but flatly ignored the control-tag emission, so nothing advanced. Same walk on **`claude-sonnet-5` + `thinking:{type:'adaptive'}` (effort medium)** ticked all 11 required boxes, tabled a deepening thread correctly, and completed. The per-turn reasoning pass is what makes the model stop and decide "does this turn cover a box → tick / table / drift." Haiku has no adaptive-thinking/effort mode at all (the param errors on it).
**How to apply:** When an agent must emit machine-read control tokens *while* doing an intelligence-heavy conversational task, don't put that on Haiku — the tokens get dropped. Use a model with adaptive thinking so the bookkeeping decision gets an explicit reasoning step. Also: a per-turn "cap N ticks" rush-guard tuned for a weak model becomes pure lag on an honest strong one — prefer a completion turn-floor + a "no hollow ticks" instruction + a mandatory synthesis box over throttling legit progress.

## Live-surface config belongs in server env, not the URL — and the two dev routes must share param names
**Why:** The Day-2 live workshop (droplet PTY) kept failing across many turns with "no terminal URL" then "bad token." Three compounding causes: (1) the `/workshop` demo route read `?url=/?token=` but the real session route (`SessionView`) read `?termUrl=/?termToken=` — carrying the demo link shape to the session gave `null`; (2) the live wss URL, token, and viewer URL rode entirely in the query string, so any normal in-app navigation to `/…/session?day=2` (no term params) could never go live, and the multi-`&` link truncated when copied; (3) `injectLiveSurfaces` had no env to read because `TERMINAL_WS_URL`/`APP_VIEWER_URL`/`TERMINAL_TOKEN` were unset in prod. Also burned time on a false "token isn't enforced" reading — an HTTP GET to the wss endpoint returns `426`/`101` *before* the token check; only a real WebSocket byte-flow test showed `4001 bad token` for a missing/wrong token.
**How to apply:** Deployment config (endpoint URLs, tokens) goes in server env — `[vars]` in `wrangler.toml` for non-secret URLs, `wrangler pages secret put` for credentials (Jonathan runs the secret command himself; the classifier blocks Claude from writing a shell token to prod, by design). Then the client link needs zero surface params. Keep dev-override param names identical across every route that renders the same canvas (accept both spellings if they ever diverge, and gate the override on ANY dev param with per-field fallback to the server payload, so partial params compose). `[vars]`/secret changes bind on the NEXT deploy and take ~15s to propagate — re-check after a wait, don't conclude "didn't work" immediately. To test whether a wss endpoint enforces auth, open a real WebSocket and watch for bytes vs a close code — never trust the HTTP-upgrade status. Quick-tunnel URLs are ephemeral (churn on droplet/cloudflared restart); a named tunnel is the durable fix.

## The Director must never coach the UI — it can't see the learner's screen; describe the ACTION, not the screen
**Why:** Pilot walk (10/16 session): Zachary asked to see all three arcs compared, then "i dont see it," then "pls take me there." The Director invented a "Canvas tab" ("tap over to that"), asserted "the scoreboard is loaded and waiting there," and finally said "I can't switch tabs for you." Root cause was NOT freelancing — the `SEEN vs SHOWN` rule literally instructed it to "tell him plainly to open the Canvas tab and look." That affordance is narrow-layout only; on his iPad side-by-side there is no tab, so obeying the rule produced the hallucination. The Director's world-model stops at the control-tag boundary: it drives the canvas via [SHOW:] but has zero visibility into the client's actual viewport/layout.
**How to apply:** Any engine prompt that tells the model to reference a specific UI element (tab/button/menu/"tap"/"swipe"/"on the right") is a latent lie — layouts vary and the model can't see which one is live. Rules: (1) "take me there" / "I can't see it" is ALWAYS answered by re-emitting [SHOW: target] that turn — navigation is the app's job, never handed back to the learner; (2) never name interface elements or places; (3) describe the action taken ("I've put the scoreboard up"), never the screen state ("it's on your screen now"). Fixed in `_session.js` via the `NO UI COACHING` rule + rewritten `SEEN vs SHOWN` + de-UI'd the Usher fallback-ask persona. This is a Walker invariant: assert the Director issues [SHOW:] and zero UI directions when a learner asks to see/find/compare something.

## Control-tag emission degrades in long context — back canvas moves with a deterministic SAY-DO repair
**Why:** Live pilot, turn ~88. The Director (Sonnet 5) NARRATED canvas moves it never performed — "I've re-shown the scoreboard", "let me bring it up again" — while `parsed.show` was null on 6 straight turns. The envelope even explicitly said `[SHOW: figure.scoreboard] when you take it up`; it still wouldn't emit the tag. The canvas can't change on a tag that was never sent, so the learner was stranded on a stale artifact no matter how many times he asked. This is the same tag-emission degradation `lessons.md` documents for Haiku, now reaching a strong model at long context. Prompt reinforcement (SAY-DO, NO UI COACHING) was necessary but NOT sufficient — the model still dropped the tag.
**How to apply:** When a control tag drives real state AND the model reliably NARRATES the action in prose, add a deterministic server backstop that reads the narration and performs the action itself — don't rely on the tag firing. Implemented as `detectClaimedShow(text)` + `resolveClaimedTarget(pack, session, text)` in `_session.js`, wired in `message.js` after Scribe/Stagehand: if `!parsed.show` and the Director claimed a show, resolve the target (noun-match against the canvas catalog, preferring the focus objective's `canvasDefault`) and force-emit it. Delivered as a `requested` canvas frame that bypasses `resolveCanvasChange`'s "unchanged" guard and makes the client DISPLAY it immediately (not queue behind a pending pill) — because a learner who can't see it needs delivery, not politeness. Bias the claim regex AGAINST false positives (an over-eager repair yanks the canvas): directional verbs (put/bring/pull) require the particle "up" + a canvas noun or it/that object, so "pulled the numbers from your memo" and "bring up a good point" don't fire. Walker invariant: assert a claimed-but-untagged show is repaired to the focus canvas.

## Regex `(?:A|B)*` where A can match B's first char never tries B — order the alternation
**Why:** Fixing a parser leak (a nested `[SHOW:]` inside a `[TABLE:]` note leaked `…re-emits; flag…]` into chat), I wrote the note group as `(?:[^\]]|\[[^\]]*\])*` to consume a whole bracket group. It did nothing — `[^\]]` matches the `[` of the nested tag as a plain char before the bracket-group branch is ever tried, so it still stopped at the first `]`. The walkthrough caught it. Fix: put the specific branch FIRST — `(?:\[[^\]]*\]|[^\]])*` — so `\[[^\]]*\]` is attempted whenever a `[` is seen, and `[^\]]` only handles non-`[` chars.
**How to apply:** In an alternation inside a quantifier, the more-specific/longer branch must precede the branch that could greedily swallow its opening character. Always test the alternation on the actual nesting case, not just the bracket-free path (which passes either way and hides the bug).

## Don't parse natural language with a regex pile — resolve against a closed set with a constrained LLM call
**Why:** The canvas-target backstop tried to answer "which canvas does the Director's prose mean?" with deterministic regex + precedence rules. It missed three times in a row (scoreboard→memo, memo→scoreboard, then "take a look at the gear memo" → wrong pane), each fix spawning the next edge case — a classic workaround chain. "Which of N known things is this sentence about" is a judgment task, not a pattern-match.
**How to apply:** When the OUTPUT space is a closed, known set (here: the canvas catalog), resolve with a cheap constrained LLM call (Haiku) whose answer is VALIDATED against that set — it can't invent a member, and it handles arbitrary phrasing. Keep a deterministic heuristic only as the fail-open fallback (network/parse miss), and gate the whole thing cheaply (a loose regex decides WHETHER to resolve, the LLM decides WHICH). This is `resolveClaimedTargetLLM` in `_session.js`. Reserve pure-deterministic resolution for genuinely closed grammars (tag parsing), not for interpreting prose.

## Parse control tags on the ARTIFACT-stripped text, never the raw turn
**Why:** Adversarial review (2026-07-07) found a HIGH bug: `parseTurn` ran every extractor (TICK/TABLE/SHOW/FIG/STAGE) over the FULL raw turn, including `[ARTIFACT:]` memo bodies. cleanText is built from the artifact-stripped text, so a control tag the Director *drafts inside a memo* (an illustrative `[FIG: figure.scoreboard :: som=$99]` or `[SHOW: figure.gtm]` documenting its method) fired as a LIVE directive — bogus value on a real figure, canvas yanked — with nothing visible in chat to explain it. The exact "canvas silently desyncs" class, from ordinary model-generated markdown.
**How to apply:** Extraction order matters. Pull the artifact writes from raw text FIRST (the body IS the content), then STRIP artifact blocks, then run all other tag extractors over `stripped` only. A directive must be actionable only where it's also visible; anything removed from the learner-visible text must also be removed from the parse surface. Regression-guarded in the engine harness (tags inside a body don't fire; a `[SHOW:]` outside it still lands).

## A heuristic text transform must exclude the STRUCTURAL neighbors of things that must stay literal
**Why:** The platform-wide comma formatter (`withThousands`) blocked only digit/letter/comma/period boundaries, so it commafied phone numbers (`415-555-1234`→`415-555-1,234`), issue refs (`#10234`), snake ids (`id_100234`), and URL path segments (`/pull/1234`) — the last corrupting markdown link *hrefs*, not just visible text. The year guard made it inconsistent (`-2000` survived, `-1234` broke). Ran on every chat message + artifact preview.
**How to apply:** For a regex substitution over prose, the boundary classes must reject the characters that *structure* literal tokens: `/ # _ -` guard phones/refs/ids/URLs. And mask whole URLs/markdown-links the same way code spans are masked before formatting — a transform that edits inside an href silently breaks the link. Some ambiguity is irreducible (a bare space-delimited zip vs a quantity); pick the reading that fits the domain and document the residual. Verify against the actual failing inputs, not just the happy path.

## A force-display flag must be consumed, not carried forward on content patches
**Why:** The `requested` canvas frame (SAY-DO force-deliver) is meant to fire ONCE. But the client's artifact-draft patch closures did `{...c, payload:{...}}`, preserving `requested:true` on every content delta; SessionView's effect (keyed on directive identity) then re-fired each draft delta and snapped a narrow-viewport learner off the chat tab mid-read.
**How to apply:** A one-shot intent flag (force-display, focus, autoplay) must be stripped once acted on, or the consumer must track "already delivered" — never let it ride along on incidental object churn. Fix: patch closures set `requested:false`; only a genuinely new server-minted frame re-asserts it.

## Recompute derived UI state on the input that actually changes it, not only on the obvious event
**Why:** The streaming jump-to-bottom button read `atBottom`, which was only recomputed in the scroll handler. A 5–79px scroll-up disabled follow (takeover fires at >4px) but left `atBottom` true (button hidden at >80px); as text streamed, the frame grew under the reader with NO scroll event (overflowAnchor:none), so `atBottom` never updated and the button never appeared — reader stranded.
**How to apply:** If a piece of derived state depends on a dimension that changes via more than one path (here: distance-from-bottom changes on scroll AND on content growth), recompute it on every such path. The streaming effect already ran on content growth — it just needed to also re-evaluate `atBottom`. Match the recompute triggers to the real inputs of the value.

## Free-form tag payloads must be removed before OTHER tag extractors run, not just from cleanText
**Why:** Fixing the depth-1 bracket leak (#7) I first only made TABLE/FIG payloads scan with a balanced-bracket helper and removed their spans from cleanText. A test still failed: a `[SHOW:]` quoted inside a TABLE note fired as a live canvas change, because the SHOW extractor ran over the full `stripped` text that still contained the TABLE tag. The leak class is broader than truncation — it's "a tag quoted inside a free-text payload gets harvested by a different extractor."
**How to apply:** In a multi-tag grammar where some tags carry FREE-FORM payloads (TABLE notes, and to a lesser degree FIG values), extract those first and REMOVE their spans from the text every other extractor sees — same discipline as stripping `[ARTIFACT:]` bodies before parsing (#1). Precedence: strip the most free-form payload first (TABLE), then the next (FIG), then run the fixed-shape tags (TICK/SHOW/STAGE/SUGGESTED) on what remains. A regex can't balance nested brackets — use a depth-tracking hand scan (`extractBalancedTags`) that returns spans, and splice spans out right-to-left so offsets stay valid.

## A fail-open resolver needs a TRI-STATE result: resolved / ran-and-declined / couldn't-run
**Why:** The SAY-DO canvas backstop chained `(await resolveClaimedTargetLLM(...)) || resolveClaimedTarget(...)`. The LLM resolver returned `null` for BOTH "I ran and there is no target" (NONE) and "I errored". The deterministic fallback is built to almost always return SOMETHING (focus default / current target), so a genuine NONE was overridden into a forced canvas yank — the backstop fired on a purely referential mention ("sharp read on the scoreboard") with no intent to navigate.
**How to apply:** When a smart primary can legitimately say "nothing to do" AND can also fail, collapsing both into one falsy value defeats the primary's judgment the moment there's a fallback. Give it a tri-state — `<result>` / `RESOLVER_NONE` (ran, declined — caller does nothing) / `null` (couldn't run — caller falls back). Only the couldn't-run case should reach the dumber fallback.

## A deterministic backstop must never override the learner's own "stop" — it enraged the pilot
**Why:** Day-1 live pilot (Zachary). He finished the day's work (13/18 objectives incl. decision + wrap) but 4 required ARTIFACT gates never ticked (ownership verifier refused consolidation memos, incl. one for an arc he'd REJECTED). `isComplete` stayed false, so the "never-orphan" backstop (`fallbackAsk`) deterministically appended "Let's keep going: <open objective>" EVERY turn — overriding the Director's own "we wrapped, see you tomorrow" and the learner's "please stop" four times. He rage-quit. The backstop existed to prevent orphaned turns; it became a machine that fought an exhausted learner.
**How to apply:** Any always-on "keep the session moving" backstop MUST yield to two signals: the learner asking to stop, and the assistant's own turn already being a wrap/farewell. Add an explicit stop-intent check (`detectStopIntent`, deterministic — false positives just skip one nag, which is always safer than trapping) and suppress the backstop when it fires. And a session needs MORE than one terminal state: "every required gate met" cannot be the only way out, or an unmet-but-unmeetable gate traps the learner forever. Add a graceful exit — stop-intent + substantial progress → close the day (marked ended-incomplete, honest for the report) so no one is ever trapped. Completion gates protect integrity; they must not become a cage.

## Ownership/quality gates must credit work done in ANOTHER modality, not just in-artifact edits
**Why:** The same pilot: the sizing memos are CONSOLIDATIONS of work the learner did live on the scoreboard (his real numbers, agreed turn by turn). But the ownership verifier asked "did the learner make substantive changes IN THIS DOCUMENT?" — so a memo that faithfully reflected his live numbers but wasn't heavily rewritten FAILED as "cosmetic acceptance." The gate demanded he re-do, in prose, work he'd already genuinely done on the board.
**How to apply:** When an artifact consolidates work the learner performed in another surface (a live figure, a chat exchange), the ownership check must trace substance to that surface, not require re-authoring inside the document. Feed the verifier the learner's live turns as the source of ownership and instruct it to PASS when the content reflects their established work + they engaged with it; lean pass in a supportive learning context; fail only genuine theater. A gate calibrated only to in-document diffs punishes the learner for the platform's own consolidate-from-live-work design.

## "Wired" is not "works" — drive the whole path or say "unverified" (100cr, terminal-watching)
**Why:** I told Jonathan twice the Director's terminal-watching worked and was "a turns-based thing." The plumbing WAS all present end-to-end — but the observable behavior wasn't there (trigger taxonomy too narrow to ever fire in a normal session; reactive channel only opened on a chat send). Inferring "works" from "the code is wired" was the mistake, and being wrong twice on the same claim torched trust. He invoked `100cr`.
**How to apply:** Before asserting a feature works, verify the observable behavior, not the presence of code: drive the entire path with a concrete input (here: a real `curl` to the deployed `/glance` returned the correct classification) or trace it end-to-end against the ACTUAL files, not memory. If you can't verify, say "wired but unverified," never "works." And when a reactive/turn-gated design is the only awareness channel for something that happens between turns, that's a design smell — name it, don't defend it.
