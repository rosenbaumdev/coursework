# Workshop VM — multi-user isolation

The Day-2 live surface (in-app terminal + app viewer) runs on the droplet
(`146.190.131.15`). This directory is the **version-controlled source** for the
droplet's bridge/proxy/systemd config — previously it lived only on the box,
hand-provisioned and untracked.

## Why this exists

The original setup ran **everything as one shared `coder` user**: one token → one
tmux session (`course`) → one `~/app` → one `~/.claude`. Any two people on it at
once shared files, shells, running processes, and the same Claude login. This
directory replaces that with **per-user isolation**: each student gets their own
unix account, workspace, tmux, `~/.claude`, bridge port, and token. The unix
account is the isolation boundary, enforced by systemd `User=`; no process ever
elevates.

```
                 cloudflared tunnel (single stable origin)
                              │
                   proxy.cjs  :9000   ── routes by /u/<user>/ path prefix
        ┌─────────────────────┼──────────────────────────┐
   /u/zachary/            /u/jonathan/               (no prefix)
   app  :8081             app  :8082                  → "default"
   bridge :7691           bridge :7692                  app :8080 / bridge :7681
   User=zachary           User=jonathan                 User=coder  (legacy)
```

- **Routing is by path**, so it keeps the *one* stable tunnel (no per-user DNS,
  no tunnel churn).
- **Per-user token**: the app hands each student a distinct `TERMINAL_TOKEN_<USER>`
  secret. A leaked token only unlocks that one user's bridge.
- **`default` route** = the legacy single-tenant `coder` backend, so the old URL
  keeps working during cutover (before the app is redeployed to emit `/u/<user>/`).

## Files

| File | Deployed to | What |
|---|---|---|
| `bridge/proxy.cjs` | `/opt/coursework/bridge/proxy.cjs` | identity-aware path router (:9000) |
| `bridge/server.mjs` | `/opt/coursework/bridge/server.mjs` | PTY↔WS bridge (one instance per user) |
| `systemd/coursework-proxy.service` | `/etc/systemd/system/` | runs the proxy |
| `systemd/coursework-bridge@.service` | `/etc/systemd/system/` | per-user bridge (`@zachary`) |
| `systemd/coursework-app@.service` | `/etc/systemd/system/` | per-user viewer (`@zachary`) |
| `provision-user.sh` | run from `/opt/coursework/` | create + wire one user |
| `routes.example.json` | copy to `/opt/coursework/routes.json` | routing table |

Per-user secrets live in `/etc/coursework/<user>.env` (root-owned, 600),
generated by `provision-user.sh` — never committed.

## One-time install (run as root on the droplet)

Assumes the current bridge deps already exist at `~coder/bridge/node_modules`
(they were built on the box — `ws` + `@lydell/node-pty`, a native module).

```bash
# 1. shared code location (world-readable; native .node must stay readable)
mkdir -p /opt/coursework/bridge
cp -a /home/coder/bridge/node_modules /opt/coursework/bridge/
#    copy the tracked source from your repo checkout of this dir:
cp workshop/bridge/proxy.cjs workshop/bridge/server.mjs /opt/coursework/bridge/
chmod -R a+rX /opt/coursework/bridge

# 2. routing table (seed with the legacy default)
cp workshop/routes.example.json /opt/coursework/routes.json   # trim to what you provision

# 3. systemd units
cp workshop/systemd/coursework-proxy.service      /etc/systemd/system/
cp workshop/systemd/coursework-bridge@.service    /etc/systemd/system/
cp workshop/systemd/coursework-app@.service       /etc/systemd/system/
systemctl daemon-reload

# 4. take over :9000 from the hand-started proxy, run it as a service
pkill -f 'bridge/proxy.cjs' 2>/dev/null || true    # stop the old manual proxy if any
systemctl enable --now coursework-proxy

# 5. shared signing secret for signed workshop tokens (Phase I) — set the SAME value
#    as the app's WORKSHOP_SIGNING_SECRET Pages secret.
printf 'WORKSHOP_SIGNING_SECRET=%s\n' "$(openssl rand -hex 32)" > /etc/coursework/signing.env
chmod 600 /etc/coursework/signing.env
#    then, from your repo checkout: npx wrangler pages secret put WORKSHOP_SIGNING_SECRET
```

Leave the existing `coursework-bridge.service` / `coursework-app.service` (the
`coder` :7681/:8080 pair) running — they are the `default` route's backend.

## Provision users

```bash
cd /opt/coursework
sudo /path/to/repo/workshop/provision-user.sh zachary  8081 7691 --copy-auth-from coder
sudo /path/to/repo/workshop/provision-user.sh jonathan 8082 7692 --copy-auth-from coder
```

`--copy-auth-from coder` reuses the Claude login you already did (shared
credential — everyone still bills to that account, but files/shells/processes
are fully isolated). Drop the flag to make the user log in with **their own**
Claude account/key on first `claude` run — true credential isolation. Swapping
later is one file per user (`~/.claude` + `~/.claude.json`), no rework.

Auth is **signed tokens** (Phase I) — no per-user token, no per-user app secret. Just
ensure the shared `WORKSHOP_SIGNING_SECRET` exists once on both sides: droplet
`/etc/coursework/signing.env` (install step 5) **and** the `WORKSHOP_SIGNING_SECRET` Pages
secret, set to the same value.

## App side (already wired in this repo)

- `functions/_students.js` / `src/students.js`: a student gains
  `workshop: { user: '<droplet-user>' }`. That maps the student's in-app session
  to their isolated backend. Currently: `zachary → zachary`,
  `zachary-test → jonathan` (so Jonathan's QA runs land on *his* instance, not
  Zachary's).
- `functions/_session.js` → `injectLiveSurfaces(directive, env, student)` stamps
  `wsUrl`/`viewerUrl` with the `/u/<user>/` prefix. The **token is minted per-connect**
  (HMAC-signed, short-lived — `functions/_workshopToken.js`) and served from
  `GET /<slug>/api/session/workshop-token`; the client (`WorkshopCanvas` → `LiveTerminal`)
  fetches a fresh one before each (re)connect. `TERMINAL_TOKEN` remains only a fallback.

## Verify

```bash
# per-user viewer (path-routed through the proxy)
curl -s 127.0.0.1:9000/u/zachary/ | head
# bridge rejects a bad token, per user
#   (open the app as /zachary → workshop → terminal should attach to zachary's shell)
systemctl status coursework-bridge@zachary coursework-app@zachary coursework-proxy
```

## Known limits

- **Viewer assets must be relative.** The viewer is served under `/u/<user>/`, so
  an app that references assets by absolute path (`/game.js`) will 404. Single-file
  games (everything inline in `index.html`, or relative `./game.js`) work. Revisit
  with a `<base>` tag or per-user tunnel host if multi-file apps land.
- **Tunnel is still the churny quick tunnel** (deferred by decision — "isolate
  users first"). The base origin URL changes on `cloudflared` restart until the
  stable `workshop.kitbord.com` named tunnel is stood up. Isolation is real; the
  base URL is not yet durable.
